# Hello, Voca Quiz Game: 언어 학습 앱

이 프로젝트는 **React.js**와 **TypeScript**를 사용하여 개발된 언어 학습 애플리케이션입니다. 사용자에게 단어 학습과 레벨별 퀴즈 기능을 제공하여 효과적으로 학습 진도를 관리하고 맞춤형 퀴즈를 제공합니다.

초기 버전 이후 구조와 인증 흐름을 전면적으로 개선하였습니다. 개선 내용은 아래 [리팩터링](#리팩터링) 항목에 정리하였습니다.

## 주요 기술 스택

- **React.js** + **TypeScript**: 사용자 인터페이스와 데이터 흐름을 위한 프론트엔드 라이브러리 및 언어
- **Vite**: 빠르고 효율적인 빌드 도구 및 개발 서버
- **pnpm**: 빠른 패키지 관리 도구

## 핵심 기능

- **회원가입, 로그인, 로그아웃**: `react-hook-form`과 `zod`를 이용한 유효성 검사 및 폼 관리
- **토큰 기반 인증**: accessToken과 refreshToken을 분리하여 관리하고, 만료 시 자동으로 재발급
- **세션 복원**: 새로고침 후에도 로그인 상태와 학습 진도가 유지
- **단어 학습 및 퀴즈 기능**: 사용자가 단어 카드를 통해 학습하고, 레벨에 맞는 퀴즈를 통해 학습 진도를 점검할 수 있는 기능
- **맞춤형 퀴즈 제공**: 사용자의 학습 진도에 따라 적합한 퀴즈를 제공하여 학습 효율성을 증대
- **공통 모달 관리**: 전역 스토어로 모달 스택을 관리하여 중첩 모달과 스크롤 잠금을 일관되게 처리
- **페이지 분기 처리**: `react-router`를 사용하여 사용자 인터페이스의 페이지 전환 관리

## 사용 라이브러리 및 도구

- **MSW (Mock Service Worker)**: API 요청을 모킹하여 독립적인 프론트엔드 개발 가능. 자격 검증과 레벨 계산까지 담당
- **Zustand**: 클라이언트 상태 관리 라이브러리 (accessToken, 공통 모달)
- **TanStack Query**: 서버 상태 관리 라이브러리 (사용자 프로필, 단어 목록)
- **Axios**: 인터셉터를 활용한 토큰 첨부 및 자동 재발급 처리
- **React Router**: 페이지 분기 처리를 위한 라우팅 라이브러리
- **TailwindCSS**, **shadcn/ui**: 스타일링 및 컴포넌트 기반 UI 구현
- **Zod**: TypeScript 기반의 스키마 선언 및 유효성 검사 라이브러리
- **React Hook Form**: 쉽고 효율적인 폼 관리를 위한 React 훅

## 폴더 구조

FSD(Feature-Sliced Design)를 적용하여 `app → pages → features → shared` 네 개 레이어로 구성하였습니다. 프로젝트 규모를 고려해 `widgets`와 `entities`는 사용하지 않았습니다.

```
src/
├── app/       프로바이더, 라우팅, 전역 스타일
├── pages/     화면 조립 (home, quiz, signup)
├── features/  사용자 액션 (auth, quiz)
├── shared/    도메인에 묶이지 않는 재사용 코드
└── mocks/     MSW 가짜 백엔드
```

임포트는 상위에서 하위로만 흐르며, 같은 레이어의 슬라이스끼리는 서로 참조하지 않습니다. 각 슬라이스는 `index.ts`로만 외부에 노출합니다.

## 리팩터링

### 상태 관리 분리

기존에는 Recoil 하나로 모든 전역 상태를 관리하였습니다. 서버에서 내려온 사용자 정보까지 전역 상태에 복사해 두다 보니, 서버 값과 화면에 보이는 값이 어긋나는 문제가 있었습니다.

클라이언트 상태와 서버 상태를 분리하였습니다.

- **클라이언트 상태(Zustand)**: accessToken, 모달
- **서버 상태(TanStack Query)**: 사용자 프로필, 단어 목록

서버에서 내려온 데이터는 Query 캐시를 단일 출처로 두고 별도로 복사하지 않습니다. 로그인 여부도 별도 상태로 두지 않고 토큰 유무에서 파생시켜, 두 값이 어긋날 여지를 없앴습니다.

### 인증 흐름 개선

기존에는 회원 목록을 클라이언트 전역 상태에 두고 비밀번호를 대조하여 로그인을 처리하였습니다. 자격 검증과 중복 검사를 모두 서버(MSW)로 옮겼습니다.

토큰은 성격에 따라 저장 위치를 나누었습니다.

|              | 저장 위치     | 이유                                          |
| ------------ | ------------- | --------------------------------------------- |
| accessToken  | 메모리        | 저장소에 남기지 않아 XSS로 탈취되지 않도록 함 |
| refreshToken | HttpOnly 쿠키 | JS가 접근할 수 없고 요청 시 자동 전송         |

accessToken이 만료되면 응답 인터셉터가 refreshToken으로 재발급한 뒤 실패했던 요청을 재시도합니다. 화면 코드는 401을 다루지 않습니다. 구현 시 다음 세 가지를 고려하였습니다.

- 여러 요청이 동시에 401을 받아도 재발급은 한 번만 수행하고 결과를 공유합니다.
- 재시도는 한 번으로 제한하여 무한 루프를 방지합니다.
- 재발급 요청 자체는 인터셉터를 거치지 않는 인스턴스로 호출하여 재귀를 방지합니다.

### 레벨 계산의 서버 이관

기존에는 클라이언트가 다음 레벨과 진행률을 직접 계산하여 전역 상태에 기록하였습니다. 클라이언트가 임의의 값을 만들어낼 수 있는 구조였습니다.

서버는 정답 여부만 전달받아 레벨을 계산하고, 클라이언트는 그 결과를 받아 화면에 반영합니다.
